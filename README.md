# Марки и ведомости — RevitStructureTools

Самостоятельный C#-плагин с тремя кнопками на отдельной вкладке **Марки конструкций**, панель **Марки и ведомости**. Может работать рядом с MyInstrumentsForRevit: у него собственные DLL и идентификатор надстройки. RevitPythonShell и Python не требуются.

## Установка

1. Соберите проект для нужной версии Revit по инструкции ниже.
2. Закройте Revit и скопируйте `RevitStructureTools.dll` в `%APPDATA%/Autodesk/Revit/Addins/2019/` (для Revit 2021 — в папку `2021`).
3. Рядом с DLL создайте файл `RevitStructureTools.addin` в UTF-8:

```xml
<?xml version="1.0" encoding="utf-8"?>
<RevitAddIns>
  <AddIn Type="Application">
    <Name>RevitStructureTools</Name>
    <Assembly>RevitStructureTools.dll</Assembly>
    <AddInId>F3873C29-5CA3-4C80-9ABD-A173E26ED328</AddInId>
    <FullClassName>RevitStructureTools.App</FullClassName>
    <VendorId>RSTL</VendorId>
    <VendorDescription>Марки и ведомости</VendorDescription>
  </AddIn>
</RevitAddIns>
```

После запуска Revit надстройка появится на вкладке **Марки конструкций**. Если Revit запросит доверие к надстройке, разрешите её загрузку. Используйте DLL, собранную для соответствующей версии Revit.

## Три команды

### Заполнить Мрк.МаркаКонструкции

Источник — **Марка** пересекаемой конструкции, при пустом значении экземпляра проверяется тип. Запись — в текстовый параметр экземпляра **Мрк.МаркаКонструкции**. Штатная привязка арматуры к основе Revit не используется.

Область — элементы **активного вида**, вложенные цели видимых семейств и стержни видимых систем армирования, как в Python. Категории целей: обычная и системная арматура, армирование по площади, семейства несущей арматуры, обобщённые модели / IFC, окна. Рассматриваются только цели с существующим параметром назначения.

Основы ищутся среди стен, перекрытий и **фундаментных плит**. Для фундаментных плит добавлена категория `OST_StructuralFoundation` с проверкой класса `Floor`; отдельные столбчатые фундаменты в поиск не включены. Основы могут находиться за пределами активного вида. Связанные модели не обрабатываются.

Алгоритм исходного скрипта с изменённой по запросу обработкой системной арматуры:

- `RebarInSystem` — по длине реального пересечения осевых линий всех существующих позиций набора с конструкциями. Применяется преобразование каждой позиции. Армирование по площади `AreaReinforcement` — по суммарному пересечению осевых линий входящих стержней. Если геометрия стержней недоступна, элемент пропускается и учитывается в общем счётчике. Штатная основа, её марка и цепочка `GetHostId()` не читаются; пересечение габаритов служит только предварительным фильтром кандидатов.
- Обычный `Rebar` — по длине пересечения осевых линий с основой.
- Семейства / IFC — по объёму пересечения тел; если есть вложенная несущая арматура, используется её геометрия. Резервная проверка пересечения габаритов сохранена только для обычной ветки, если ни одна булева операция не удалась.
- Окна — по объёму пересечения габаритов, как в Python.
- **Переход «верхняя стена → плита → нижняя стена»**: если у одного стержня подтверждены реальные пересечения с двумя разными стенами и плитой между ними, выбирается Марка нижней стены независимо от длины / объёма пересечения и префикса. Правило проверяется отдельно для каждого стержня набора, а для семейств / IFC — для каждого анализируемого тела. Пересечения разных стержней не объединяются в ложный переход. Без плиты между стенами, при наличии только одной стены или при неполной проверке дополнительный приоритет не применяется. Если у выбранной нижней стены нет Марки, запись пропускается. Строгая ветка гильз 231 и окна сохраняют прежние правила.
- Префикс **Арм.ПрефиксФормы = В** — сначала самое низкое пересечение, затем наибольшая длина / объём. Буква «В» кириллическая. Ветка окон не учитывает префикс.
- Семейства с **231** в имени семейства экземпляра или его родителя — только реальные тела гильзы категории «Несущая арматура», без подстановки габарита родителя. Ошибка проверки хотя бы одной основы означает пропуск записи для этой цели.
- Для стен во всех геометрических ветках строится временное тело по внешнему плоскому контуру без внутренних отверстий. Вырезы, связанные с внешним контуром, остаются. Криволинейные / неплоские стены не аппроксимируются, выводится диагностика. Модельные стены не изменяются.

### Анализ ВРС / ВРБ

Обрабатывается **вся текущая модель**. Состав категорий сохранён из Python: несущая арматура и обобщённые модели; перекрытия и только несущие стены. Фундаментные плиты добавлены в поиск основы первой команды, состав анализа ВРС / ВРБ не расширялся.

Для арматуры / ОМ: **Мрк.МаркаКонструкции → Арм.Группа ВРС**.

Для бетона: **Марка → Орг.ГруппаВедомостьРасходаБетона**. При чтении Марки экземпляра сначала используется встроенный `ALL_MODEL_MARK`. При пустой исходной марке проверяется тип.

Окно выбора режима сохранено:

- **Да** — самое частое непустое значение группы для марки, совместно среди арматуры / ОМ и бетона. Значение записывается всем элементам марки, включая заполненные иначе. При одинаковой максимальной частоте разных значений марка пропускается.
- **Нет** — пустая редактируемая таблица: Марка / Арматура и ОМ / Бетон / Всего / Значение группы. Одинаковая марка в обеих группах имеет одну строку. Пустая ячейка означает пропуск; непустая — запись всем элементам марки в соответствующий целевой параметр.
- **Отмена** или закрытие таблицы — без изменений.

Дубли имён и нетекстовые параметры фиксируются как ошибки. Пробелы по краям марки убираются; непустые значения групп сохраняются буквально, как в скрипте.

### Очистить Мрк.МаркаКонструкции

Обрабатываются **все экземпляры текущей модели**. Существующий доступный для записи текстовый параметр **Мрк.МаркаКонструкции** очищается. Отдельно считаются очищенные, уже пустые, пропущенные элементы и ошибки. Типы не изменяются. Команда работает сразу, как исходный скрипт.

## Отчёты и отмена

### Скорость заполнения Мрк.МаркаКонструкции

На время одного запуска сохраняются осевые линии, габариты, признаки семейства и префиксы. Пересечение одной и той же пары геометрических объектов рассчитывается один раз: результат повторно используется при обработке армирования по площади и его отдельных стержней, а также родителя и общей вложенной геометрии. Кэши разделены по режимам геометрии и очищаются после команды.

Перед точной операцией выполняется консервативный отсев по габаритам отдельных тел и прямых отрезков. Проверяются все восемь углов габарита тела с учётом преобразования; касания и близкие границы передаются на точный расчёт. Для дуг и сплайнов отсев по концам не применяется. При недоступном габарите выполняется точная проверка. Объём и длина положительных пересечений по-прежнему рассчитываются Revit.

В отчёте отображается время анализа и время записи. Ускорение зависит от состава модели и количества повторных пар; замер на 1000 реальных элементов нужно выполнить в Revit.

Вместо консоли Python подробности открываются в окне отчёта: полный список соответствий, пропусков и ошибок, кнопка **Сохранить отчёт…** для UTF-8 TXT. Изменения каждой команды выполняются одной транзакцией и отменяются стандартной командой Revit **Отменить**. Итоги показываются только после успешного подтверждения транзакции.

Поэлементные сообщения о параметрах только для чтения не выводятся и ошибками не считаются; остаётся общий счётчик пропусков. В заполнении Мрк.МаркаКонструкции такие элементы, включая вложенные, пропускаются до геометрического анализа. Значения родителя обрабатываются по обычным правилам; попытки напрямую записать зависимый параметр вложенного элемента не выполняются. В ВРС / ВРБ доступные значения вложенных элементов по-прежнему участвуют в анализе частот, но недоступная запись не добавляет ошибок.

Сообщение с ID об отсутствии пересечения выводится только после успешной геометрической проверки. Пересечения проверяются и у конструкций без Марки: отсутствие Марки не выдаётся за отсутствие пересечения. Недоступная геометрия и служебные причины пропуска гильз учитываются суммарно, без длинных технических строк. Неожиданные исключения анализа или записи по-прежнему отражаются в отчёте.

Параметры не создаются и не привязываются автоматически: они должны существовать в модели. Команды недоступны без открытого проекта и в редакторе семейства. Доступность кнопок не зависит от временного `Document.IsReadOnly` в контексте проверки ленты; возможность записи Revit проверяет при открытии транзакции команды.

## Исходники и сборка

Откройте `RevitStructureTools.sln` в Visual Studio с компонентом разработки .NET Framework либо используйте установленный .NET SDK и соответствующий .NET Framework Developer Pack:

```powershell
dotnet build .\RevitStructureTools.sln -c Release -p:RevitVersion=2019
dotnet build .\RevitStructureTools.sln -c Release -p:RevitVersion=2021
```

Для 2019: `.NET Framework 4.7`, x64, точные пакеты `Revit.RevitApi.x64` и `Revit.RevitApiUI.x64` версии `2019.0.0`. API используется только при компиляции и не поставляется в папке надстройки. Установленный Revit 2019 для сборки не требуется; при первом восстановлении нужен доступ к NuGet.

Для 2021: `.NET Framework 4.8`, x64, API из установленного `C:/Program Files/Autodesk/Revit 2021`. Путь можно переопределить свойством MSBuild `RevitInstallDir`.

Результат сборки — `src/RevitStructureTools/bin/2019/Release/RevitStructureTools.dll` или `src/RevitStructureTools/bin/2021/Release/RevitStructureTools.dll`. Служебные файлы Visual Studio и результаты компиляции исключены через `.gitignore`.

## Проверка перед применением

Успешная компиляция не заменяет запуск в Revit. Геометрия, фактическая видимость, доступность параметров и запись на конкретной модели требуют проверки на её копии. Сценарии: обычная / системная / вложенная арматура, фундаментная плита, семейство 231, префикс В, окна; оба режима ВРС / ВРБ, равенство частот, отмена таблицы; очистка и отмена транзакции.

Основа требований Revit 2019: [Autodesk — Development Requirements](https://help.autodesk.com/cloudhelp/2019/ENU/Revit-API/files/Revit_API_Developers_Guide/Introduction/Getting_Started/Welcome_to_the_Revit_Platform_API/Revit_API_Revit_API_Developers_Guide_Introduction_Getting_Started_Welcome_to_the_Revit_Platform_API_Development_Requirements_html.html).
